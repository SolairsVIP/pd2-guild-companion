# 营地 · PD2 S14 公会助手

独立中文网页，包含真实 HTTP 后台和 SQLite 数据库。每个部署服务一个公会，成员通过一次性邀请链接注册。不是 PD2 官方产品，也不是游戏内注入插件。

## 下载与快速开始

本项目以 MIT 许可证提供源码，可下载、自行部署和修改。需要先安装 **Node.js 24 或以上版本**；没有额外 npm 依赖。

1. 在仓库页面选择 **Code → Download ZIP**，或下载发布页中的源码 ZIP。
2. 解压后进入包含 `package.json` 的目录，打开终端。
3. 运行 `npm run demo`，浏览器打开 <http://127.0.0.1:3215> 体验虚构演示数据。
4. 正式使用时运行 `npm start`，打开 <http://127.0.0.1:3214> 创建自己的公会和会长账号。

Windows 若提示 PowerShell 脚本执行受限，将上述 `npm` 换成 `npm.cmd`。
源码不包含任何真实公会数据。首次运行会在本机新建数据库，不会自动连接其他人的公会。
下载源码运行后，成员需要连接到同一台已部署的服务器才能共享数据；每个人在自己电脑运行会创建彼此独立的实例。

版本记录见 [CHANGELOG.md](CHANGELOG.md)，开发说明见 [CONTRIBUTING.md](CONTRIBUTING.md)。

### 生成可分发源码包

Windows PowerShell 中执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1
```

生成 `dist/pd2-guild-companion-0.1.0.zip` 和 SHA-256 校验文件。上述执行策略参数仅对本次 PowerShell 进程生效。打包使用明确的源码清单，排除数据库、环境配置、Git 元数据及本地输出。`dist/` 不纳入 Git，适合单独作为发布附件上传。

代码许可证不覆盖 PD2 的商标、游戏内容、官方接口和远程图片；相关内容的权利仍归各自权利人。

## 已实现

| 功能 | 首版行为 |
| --- | --- |
| 人员登记 | 昵称、角色、职业、等级、BD、SC/HC、天梯/非天梯、常用时段；名册搜索与模式筛选 |
| 集体消息 | 会长向全体或指定模式发布站内公告；成员确认已读，显示已读人数 |
| 拼车 | 发起地图/练级/开荒/Boss 活动、预约出发、2–8 人、报名/退出/结束、满员限制；房间只向已报名者及会长返回 |
| 装备互助 | 发布装备名称和属性文本、预留、取消预留、分享者确认交付或撤回；防止重复预留 |
| 快速导入与装备图片 | 游戏内指向物品按 Ctrl+C，兼容 PD2 Trader 使用的单件装备 JSON；分享表单解析属性并生成 PNG，可下载或复制图片，也支持普通文本；从已发布装备可再次生成图片 |
| 贡献徽章 | 每条装备确认交付后累计一次成功分享；1 / 5 / 10 / 25 / 50 次对应五档徽章，达标后手动领取，名册展示；后台校验门槛并防止重复领取，记录随数据库持久保存 |
| 角色装备 | 官方链接或 JSON 导入快照；只展示角色与佣兵的穿戴槽位窗口，支持主/备用武器切换、悬停属性、点击固定、Esc 关闭和手机点按；固定属性后可填入分享草稿 |
| 多人共享 | 服务器数据库统一保存；页面每 8 秒刷新，切回标签页时刷新 |
| 账号 | 首次创建会长、邀请注册、密码哈希、7 天登录会话、注销；一次性邀请 7 天有效 |

组队与装备领取由后台校验模式一致。切换个人模式前需要退出/结束当前拼车，并处理自己仍在分享或预留的装备。

快速复制使用的是游戏 Ctrl+C。PD2 Trader 的查价快捷键 Ctrl+D 会恢复之前的剪贴板，因此查价结束后不一定能直接粘贴装备。网页只在点击“读取剪贴板”时读取一次，不监听游戏或后台剪贴板；浏览器拒绝读取时，直接在原始数据框按 Ctrl+V。JSON 不含游戏模式，导入后按当前登记模式发布，请先确认模式和分类。PNG 是本地排版生成的文字装备卡，不是游戏截图；图片不自动发布到群聊或上传到服务器。

## 运行

需要 **Node.js 24 或以上版本**。无需安装 npm 依赖。

```powershell
npm.cmd start
```

打开 [http://127.0.0.1:3214](http://127.0.0.1:3214)，首次填写公会名称和会长资料。在成员名册点击“邀请成员”，将生成的链接交给一位成员；每位成员分别生成一个邀请。

首次设置仅接受服务器本机连接。请先在本机初始化，再开放网络访问。不要将尚未初始化的服务放在公网反向代理之后。

### 演示预览

```powershell
npm.cmd run demo
```

打开 [http://127.0.0.1:3215](http://127.0.0.1:3215)。演示账号 `demo`，密码 `CampDemo2026!`。包含 7 位虚构成员、3 支队伍、3 件装备及 2 条公告。演示数据仅保存在内存，关闭后即消失，与正式数据库完全分开。演示端口仅监听本机，不要作为正式公会部署。

### 自动检查

```powershell
npm.cmd test
```

集成测试使用独立临时数据库，通过真实 HTTP 覆盖认证/邀请、公告权限与已读、并发报名与模式隔离、房间可见性、并发预留及交付、跨站请求保护、注销与重启持久化。

### 导入官方角色装备

登录后点击导航中的“角色装备”，或打开 `/armory`。

1. 输入角色名，或 `https://projectdiablo2.com/character/角色名` 链接，点击“从官方读取并保存到公会”。后台只请求 `https://api.projectdiablo2.com/game/character/角色名`，不发送游戏账号密码或登录 Cookie，不跟随重定向。
2. 如果后台无法连通官方接口，展开“官方 JSON 手动导入”。在浏览器打开页面内的官方 JSON 链接，复制全文，或将保存的 JSON 文件选入后解析保存。文件限 2 MB。
3. 成员名册中可以查看已保存的装备快照。快照会显示官方数据时间、本站导入时间、角色模式及来源；手动导入明确标记为来源未验证。
4. 在自己保存的快照中选一件物品，点击“填入装备分享表单”。程序会填好名称、分类、属性及来源，**仍需成员确认当前持有物品，再提交发布**。快照模式与成员登记模式不一致时禁用此按钮。

每位成员保存一份当前快照，重新导入替换旧快照。公开角色数据不能验证账号归属；本站也不会把“能输入这个角色名”当成所有权证明。当前只读取官方返回的数据，不能据此断言包含全部仓库、所有角色或公会仓库。属性保留官方接口返回的英文文本。

接口请求有 12 秒超时、2 MB 响应上限、5 分钟缓存及每成员每分钟 10 次导入限制。接口格式变化、服务器网络不可达或官方拒绝访问时，会显示错误并保留旧快照。单元与 HTTP 测试不依赖公网；真实联网能力仍需在部署主机上验证。

## 公网发布需要什么

需要一处持续运行 Node.js 后台的主机或托管平台，并提供**持久化磁盘**。单纯静态网页托管无法运行这个版本的后台。一个小型部署可以让同一公会成员共同使用；实际人数上限需要按服务器配置压测。

部署步骤：

1. 在服务器的本地连接中运行服务并创建正式公会。可通过 SSH 本地端口转发访问；此时先不要开放反向代理给外网。
2. 将应用作为长期服务运行。数据库目录必须持久化，不可随每次部署重建。
3. 使用域名及 HTTPS 反向代理访问后台。正式 HTTPS 环境设置 `COOKIE_SECURE=true`。
4. 成员必须通过**公网域名**生成的邀请链接加入；本机 `127.0.0.1` 链接不能发给其他人使用。
5. 做一次完整的邀请注册、跨设备报名和重启检查，再正式开放给成员。

可配置环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址；容器内用 `0.0.0.0`，由宿主/平台限制暴露范围 |
| `PORT` | `3214` | 后台端口 |
| `DB_PATH` | `data/guild.sqlite` | SQLite 文件绝对路径；部署时指向持久化卷 |
| `COOKIE_SECURE` | `false` | HTTPS 公网部署设为 `true`；本机 HTTP 预览保持 `false` |

PowerShell 示例（同机 HTTPS 反向代理的后台）：

```powershell
$env:COOKIE_SECURE = 'true'
$env:PORT = '3214'
npm.cmd start
```

如果使用 Docker，仓库提供 Dockerfile。先通过仅绑定本机的宿主端口完成设置，再连接 HTTPS 反向代理。不要在本机 HTTP 初始化阶段启用 Secure Cookie，否则浏览器不会正常保存会话。

```powershell
docker build -t pd2-guild-camp .
docker run -d --name pd2-guild-camp -p 127.0.0.1:3214:3214 -v pd2-guild-data:/app/data pd2-guild-camp
```

## 数据与备份

正式数据在 `data/guild.sqlite`，程序运行时还会产生 SQLite 的 WAL/SHM 文件。**不要在运行中只复制主数据库文件**；可以停止服务后备份整个 `data` 目录，恢复时也在服务停止状态操作。演示模式不写入这些文件。

## 当前边界

- 角色装备支持手动触发的官方公开数据读取和 JSON 导入；不会后台定时同步 PD2 公会名单、账号私有仓库或角色在线状态。
- “最近活跃”指网站两分钟内活跃，不表示游戏在线。
- 装备可手动登记，也可从角色快照填入名称和属性，仍需在游戏内手动交易；尚无截图上传、OCR 或登录后的账号库存对接。
- 集体消息目前为站内公告，没有游戏内群发、QQ/微信/Discord 推送或离线通知。
- 首版一个账号登记一个角色，一个实例一个公会，一个会长；尚无密码找回、会长转让、踢人/封禁、邀请撤销或管理审计。正式扩大使用范围前应补齐账号管理。
- 尚未部署公网、未完成生产环境压测；没有对接登录后的交易发布接口或公会接口。

- `public/`：中文界面，支持桌面与手机布局。
- `demo.js`：隔离的演示服务。
- `test/server.test.js`：HTTP 集成测试。
- `DESIGN.md`：功能流程、设计约定及待确认事项。
